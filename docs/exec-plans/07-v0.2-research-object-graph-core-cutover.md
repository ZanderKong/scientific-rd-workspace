# 2. 本次产品语义冻结

本计划执行期间，不再重新讨论下列核心语义。实现必须围绕它们展开。

## 2.1 七类科研对象

所有科研记录统一建模为 `ResearchObject`，内置七个稳定 `kind`：

```text
material     原料 / 试剂
sample       样品
equipment    设备
process      过程 / 操作
data         数据 / 测试结果
experiment   实验
project      项目 / Vault / Scope
```

### 用户语义

- **Material 原料 / 试剂**
  - 外购化学品、原材料、基材、试剂、批次原料。
  - “供应商声明的静态信息”属于 Material 属性。
  - 实际测试得到的水分、纯度、粒径等应形成 Data，不直接覆盖 Material 自身属性。

- **Sample 样品**
  - 某次制备、处理或实验后实际得到的物理对象。
  - Sample 自身只保存“它是什么”的属性。
  - 前驱体、使用原料、使用设备、制备过程、测试数据不重复写进 `properties_jsonb`，应由 Graph 推导。

- **Equipment 设备**
  - 制备设备、测试仪器、环境装置。
  - 如 Avantes、万能试验机、浸渍槽、烘箱等。

- **Process 过程 / 操作**
  - 真实发生的一次制备、处理、测试或分析 Activity。
  - 是输入对象、设备、输出对象之间的连接器。
  - 详细步骤写正文，关键参数结构化。

- **Data 数据 / 测试结果**
  - 一次语义完整、具有统一 provenance 的测试、采集或分析结果。
  - 不是一个数字一个 Data。
  - 也不是一个 Sample 一生的全部数据塞进一个 Data。

- **Experiment 实验**
  - 科研上下文集合。
  - 直接组织 Process、Sample、Data。
  - 不重复把 Material、Equipment 强塞进 contains；它们从 Process 图中得到。

- **Project 项目**
  - 类似 Obsidian Vault 的业务 Scope。
  - 切 Project 相当于切换当前科研视图。
  - Project 仍然是 ResearchObject，但其“scope”由专门字段实现，而不是强制用大量 contains 边重复表示。

# 3. 核心关系冻结

Canonical relation type 只保留：

```text
contains
uses
produces
precedes
related_to
```

## 3.1 contains

本计划中：

```text
Experiment ─contains→ Process
Experiment ─contains→ Sample
Experiment ─contains→ Data
```

Project 的作用域归属优先由 `project_scope_id` 表示，避免同时维护：

```text
project_scope_id
+
Project ─contains→ every object
```

两份事实源。

Project 页面在 UI 上仍然表现为“包含实验”，但后端可以由：

```text
kind=experiment AND project_scope_id=<project_id>
```

计算。

## 3.2 uses

`uses` 的 source 必须是 Process。

允许 target：

```text
Material
Sample
Equipment
Data
```

关系 metadata 至少支持：

```text
role
quantity.value
quantity.unit
note
```

典型例子：

```text
Process uses Material KI
role=additive
quantity=1 g

Process uses Sample SMP-012
role=precursor

Process uses Equipment EQP-002
role=equipment
```

“前驱体”不是 Sample 自身的冗余字段。

前驱体事实来自：

```text
Process ─uses(role=precursor)→ Sample A
Process ─produces→ Sample B
```

Sample B 的页面把这个关系投影成：

```text
前驱体：Sample A
```

## 3.3 produces

source 必须是 Process。

target 仅允许：

```text
Sample
Data
```

例如：

```text
浸渍 Process → Sample
光谱测试 Process → Data
数据处理 Process → Data
```

## 3.4 precedes

用于：

```text
Process → Process
```

表达显式时间 / 工艺先后。

如果已有 input / output 已经能唯一推导顺序，不强制创建 `precedes`；它用于无直接物料传递但需要表达顺序的情况。

## 3.5 related_to

仅作为弱关系兜底。

不得为了偷懒把本可表示为 `uses / produces / contains` 的关系全部塞成 `related_to`。

允许 Luna 根据 SQLAlchemy / Alembic 实际需要做小幅命名调整，但不得改变以下语义。

## 5.1 `research_objects`

建议：

```text
id                  UUID PK
code                VARCHAR unique
kind                VARCHAR
title               VARCHAR
status              VARCHAR
project_scope_id    UUID nullable FK -> research_objects.id
type_version_id     UUID FK -> object_type_versions.id

```

`kind`：

```text

sample

process
```

### project_scope_id

- Project 本身：`NULL`
- Project-scoped Experiment / Process / Sample / Data：必须指向一个 `kind=project` 的对象。
- Material / Equipment：
  - 可为 NULL：全局 Library
  - 可为 project id：项目私有原料 / 设备

- project-scoped relation 不允许偷偷跨项目，除非 target 是允许跨项目引用的全局 Library 对象。

### content_document

继续使用 BlockNote document JSON。

不得把结构化属性写进正文替代 schema。

## 5.3 `object_type_versions`

```text

object_type_id

is_active
```

规则：

- `(object_type_id, version)` unique。
- 已发布 version immutable。
- 对象永久引用精确 `type_version_id`。
- 新 schema 创建新 version，不原地修改历史 schema。
- API 保存对象时根据 `type_version_id.json_schema` 做 server-side validation。
- unknown fields 不得静默丢弃。

## 5.4 `object_relations`

建议：

```text
id
source_object_id
target_object_id
relation_type
role nullable
properties_jsonb
created_at
updated_at
```

至少建立：

```text
(source_object_id, relation_type)
(target_object_id, relation_type)
```

索引。

建议 unique：

```text
(source_object_id, target_object_id, relation_type, role)
```

如果实际 PostgreSQL nullable unique 语义造成重复边漏洞，使用合适的 expression / `NULLS NOT DISTINCT` / service validation。

必须验证：

- 不允许 self-edge。
- `uses` 的 source / target kind 合法。
- `produces` 的 source / target kind 合法。
- `contains` 的 source / target kind 合法。
- `precedes` 只允许 Process → Process。
- project scope 兼容。
- relation mutation 必须显式失败，不静默 coerce。

---

## 5.5 `object_revisions`

```text
id
object_id
revision_number
snapshot_jsonb
snapshot_sha256
change_note
created_at
```

unique：

```text
(object_id, revision_number)
```

snapshot 至少冻结：

```text
object:
  id
  code
  kind
  title
  status
  project_scope_id
  object_type
  type_version
  properties
  content_document

direct_relations:
  outgoing [...]
  incoming [...]

attachments:
  metadata only

data_payloads:
  summary / hash metadata only
```

原则：

- revision snapshot immutable。
- relation 后续变化不得改变历史 revision。
- binary 不复制。
- 大量 data points 不重复塞 snapshot，只记录 payload hash / summary / source identity。
- hash 使用 canonical JSON。
- revision number 单调递增。

# 9. GraphQueryService

必须建立一个显式 domain service，例如：

```text
GraphQueryService
```

不要把复杂 traversal 散在 router / React 页面里。

必须支持：

```text
get_direct_relations(object_id)

get_experiment_context(experiment_id)
trace_sample_lineage(sample_id, depth)

```

## Sample context 必须分层

返回结构必须区分：

```text
direct
upstream
downstream
experiment_context
```

不得返回一个没有语义区分的：

```text
related_objects[]
```

### direct 至少包含

- 当前 Sample
- 直接 producing Process
- producing Process 使用的：
  - precursor Sample
  - Material
  - Equipment
- 当前 Sample 直接相关测试 Process
- 当前 Sample 直接生成的 Data

### upstream

递归前驱体来源：

```text
Sample A
→ Process
→ Sample B
→ Process
→ Sample C
```

并能汇总到需要的 depth。

### downstream

由该 Sample 继续作为 input / precursor 后生成的 Sample。

### Data 语义

前驱体 Data 只能出现在 upstream。

不得混入：

```text
当前样品数据
```

# 10. Cycle 安全

Object graph 可以包含弱关系环，但 provenance / lineage traversal 必须安全。

必须防止：

- self relation
- Sample lineage 明显成环
- Process precedes cycle
- Experiment contains itself

所有递归 API：

- 有 visited set / cycle guard；
- 有默认 depth；
- 有 hard max depth；
- 不允许用户发无限递归查询。

建议：

```text
default depth = 3
max depth = 8
```

具体可微调，但必须 bounded。
