# Plan 07.1 — v0.2 Core Semantic Stabilization

This repository copy records the execution contract supplied in `/Users/kong/Downloads/07.1-v0.2-core-semantic-stabilization.md`. The attached document is the plan specification; implementation decisions below preserve its canonical object-graph semantics.

## Acceptance contract

- `sample` remains a canonical object kind. `precursor`, `subject`, `reference` and `control` are roles on `uses` edges, with documented alias normalization.
- Only `precursor` drives lineage and only `subject` drives current Data. `contains` is Experiment ownership for Process/Sample/Data; consuming an upstream sample does not transfer ownership.
- A Process may have many outputs and precursor inputs. A Sample/Data has at most one producer; an owned Process/Sample/Data has at most one Experiment owner. `related_to` is never canonical provenance.
- PostgreSQL migration `0002_v0_2_semantic_stabilization` adds defaults, checks and partial unique indexes without rewriting migration `0001`.
- Central service validation covers kind, scope, role, ownership, cardinality, precursor cycles and Process `precedes` cycles. Scope mutation revalidates existing edges and graph conflicts return HTTP 409.
- Process composition is a single desired-state `GET/PUT /api/v1/processes/{id}/composition` transaction. New Sample/Data outputs are created and auto-owned atomically.
- BlockNote JSON is preserved. Search filters are applied before pagination; summaries are aggregate API responses; chart coordinates use real X values; lineage UI renders backend edges as a tree.
- Seed data is repeat-safe and demonstrates preparation/measurement separation plus the `SMP-001 → SMP-002/SMP-004` branch and `SMP-002 → SMP-003` continuation.
